# Validation Study: C++ Crash Explainer (v0.2.1)

## Objective
Evaluate whether `cpp-crash-explainer` measurably improves a beginner's ability to identify, understand, and debug C++ memory safety errors compared to raw AddressSanitizer/LeakSanitizer diagnostic reports.

---

## Participant Profile
- **Target Audience:** 3 to 5 Computer Science students or junior programmers who have taken or are currently taking an introductory C / C++ or Data Structures course.
- **Prerequisites:** Familiarity with basic pointers, arrays, loops, and dynamic allocation (`new` / `delete`). Prior experience with AddressSanitizer is **not** required.

---

## Exercise Setup

Each participant is presented with two formats for the same memory errors:
1. **Condition A:** The raw diagnostic output produced by AddressSanitizer (GCC/Clang).
2. **Condition B:** The explanation generated by `cpp-crash-explainer`.

---

## Test Scenarios

### Scenario 1: Heap Buffer Overflow
- **Raw Input:** `tests/fixtures/heap_buffer_overflow.txt`
- **C++ Code:**
  ```cpp
  #include <iostream>

  int main() {
      int* numbers = new int[10]; // valid indices: 0 to 9 (40 bytes)
      for (int i = 0; i <= 10; ++i) { // Bug: off-by-one loop accessing index 10
          numbers[i] = i * 2;
      }
      delete[] numbers;
      return 0;
  }
  ```
- **Evaluation Questions:**
  1. What type of memory error occurred?
  2. On which line in the source code did the program crash?
  3. Where was the memory buffer originally allocated?
  4. What specific code change is needed to fix the bug?

---

### Scenario 2: Heap Use-After-Free
- **Raw Input:** `tests/fixtures/heap_use_after_free.txt`
- **C++ Code:**
  ```cpp
  #include <iostream>

  struct User {
      int id;
  };

  int main() {
      User* user = new User{42};
      delete user; // Deallocated here

      std::cout << user->id << std::endl; // Bug: accessed after deletion
      return 0;
  }
  ```
- **Evaluation Questions:**
  1. What happened to the object before it was accessed?
  2. On which line was the memory freed?
  3. On which line did the illegal access take place?
  4. How can the developer prevent this bug?

---

### Scenario 3: Memory Leak
- **Raw Input:** `tests/fixtures/memory_leak.txt`
- **C++ Code:**
  ```cpp
  #include <iostream>

  void create_data() {
      int* array = new int[10]; // Bug: allocated but never deleted
      // function exits without delete[]
  }

  int main() {
      create_data();
      return 0;
  }
  ```
- **Evaluation Questions:**
  1. Did the program crash during execution, or did it complete?
  2. How much memory was leaked?
  3. Which function was responsible for allocating the leaked memory?
  4. What is the recommended modern C++ fix (e.g. RAII / `std::vector`)?

## Evaluation Rubric
- **Identification Speed:** Measured in minutes/seconds from opening the prompt to answering questions 1–3.
- **Root Cause Accuracy:** Scored 0 (incorrect), 1 (partially correct), or 2 (fully accurate description of cause and fix).
- **Subjective Rating (1–5 scale):**
  - "How confident are you that you understand where and why this bug occurred?"
  - "How helpful were the suggested next steps?"
